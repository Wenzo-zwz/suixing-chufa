# 随性出发：固定网址网页版

用户明确要求先做成 GitHub 上随时可访问的网页。沿用已确认功能与视觉，先发布现有可运行功能；不把已有多人流程改为按钮占位，也不承诺当前有限目录已覆盖全国全量资料。

## 方案

GitHub Pages 托管静态网页；原来依赖本机 Node 的 API 迁到 Sites 的云端服务，D1 保存多人房间。GitHub 仓库保存完整网页与后端代码。仅用 Pages 无法保留真实多人房间；继续使用临时隧道依赖电脑在线，不能满足此需求。现有批准的产品设计保持，实施不另设确认门槛。

新工作目录 `D:/Codex/小程序/suixing-chufa-web`；保留原小程序原型目录。前端继续使用 ES modules 与现有渲染器；服务端使用 Sites 提供的 Vinext starter（保留 sites() 构建集成），API 复用目录与领域逻辑。

## 约束

- 四种跟手玩法、个人、自填、收藏、旅程、多人全员准备与同轮唯一结果均保留。
- 网页使用已生成的小旅行者坐纸飞机头像。去掉虚假的手机状态栏/微信胶囊，手机和电脑都可以操作。
- Pages 站点部署在仓库子路径；资源相对路径，分享链接保留子路径。
- CORS 仅允许当前云站点、`https://wenzo-zwz.github.io` 与明确配置的本地验证来源。
- 公共服务的客户端身份需要私密令牌。浏览器保留公开 clientId 和独立随机 clientToken；只有 ID 会出现在房间成员中。服务端将令牌哈希与 ID 绑定，其他成员无法仅凭公开 ID 冒充。
- D1 记录保存完整房间领域状态与独立 revision；以 revision 比较交换更新，处理同版本同时准备/抽取，不丢更新。同轮重试返回同一个持久结果。
- 不保存原始指针/运动数据。收藏、旅程仍本机浏览器保存，明确说明。
- 页面保持“示例目录、非实时数据”说明。无需用户的电脑开机，但不能保证所有网络环境均无阻碍。
- 仓库不提交凭据、本机运行状态、旧临时隧道信息、node_modules 或打包输出。

## 验收

先测房间持久化/重载、CAS冲突、双人同时ready/draw、令牌冒充拒绝、CORS和请求体限额。继续运行原67项规则与全部浏览器回归。Pages子路径验证首页、四种手势、收藏、分享加入；云端验证两独立浏览器真实共同结果。最后检查 GitHub 仓库、Pages 状态与公网 HTTPS 页面，交付实测网址。
